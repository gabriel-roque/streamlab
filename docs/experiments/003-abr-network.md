# 003 — ABR Under Network Variation

## Question

Does the player switch variants before the buffer runs out without oscillating
too much?

## Procedure

Generate an HLS master package with `scripts/generate-hls.sh` and serve the
directory from a static HTTP server, or use the remote `abr-lab` fixture. For the
local API path, use DevTools, `tc netem`, or a proxy for 10, 5, 1.5, and 0.5 Mbps
profiles. Change bandwidth during playback and repeat five times per profile.

```bash
scripts/smoke-http.sh --url http://localhost:3000 \
  --path /api/healthz
```

To verify only the manifest for a local upload `ID` that is already `READY`, use
`/api/videos/ID/playback/hls`:

```bash
scripts/smoke-http.sh --url http://localhost:3000 \
  --manifest /api/videos/ID/playback/hls --kind hls
```

The API publishes a local playlist, not a `/video/ID/master.m3u8` route; in the
current processor it is not an ABR master. The master with variants belongs to
the package generated by the scripts. The public `abr-lab` fixture must be
tested through the external URL returned by `/api/videos/abr-lab/playback`, not
through the local manifest endpoint. The web player uses `hls.js` when the
browser does not play HLS natively.

## Measure

Startup, rebuffer ratio, buffer_seconds, average bitrate, switches per minute,
reaction time to a drop, and recovery after restoration. Record the variant
sequence and estimated throughput per segment.

## Hypothesis and Criteria

A conservative policy should reduce quality before rebuffering and increase it
gradually. Repeated oscillation or rebuffering during a switch is a failure to
investigate, not merely a throughput result.
