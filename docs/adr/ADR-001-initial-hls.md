# ADR-001: HLS as the Initial Protocol

- **Status:** accepted
- **Data:** 2026-09-10

## Context

The first player needs to play adaptive VOD in common browsers and allow simple
inspection of manifests and segments.

## Decision

Start with HLS VOD and MPEG-TS segments. The local processor also publishes a
DASH manifest for comparison. The master ladder with variants is generated by
the lab scripts; the fixture used when FFmpeg is unavailable is a single-media
HLS playlist, not a master.

## Alternatives

- Deliver progressive MP4: simple, but without ABR and with poorer cache control.
- Start with MPEG-DASH: a good adaptive model, but it adds a second compatibility
  chain before the basic pipeline is validated.

## Consequences

Local playback exposes HLS at `/videos/{id}/playback/hls` and DASH at
`/videos/{id}/playback/dash`; the HLS manifest endpoint uses
`application/vnd.apple.mpegurl`. HLS does not eliminate the need to validate
Range, caching, and QoE. Public fixtures are remote and do not pass through the
local packager.
